# Portal — перенос файлов через порталы

Portal — настольное приложение для Windows 10/11, которое переносит файлы через небольшие плавающие окна. Привяжите портал к папке и перетащите на него файл из Проводника.

Приложение работает локально, без облака, регистрации и прав администратора. Интерфейс на русском языке. Создано на Python и PySide6.

## Возможности

- Несколько независимых порталов поверх окон с выбором цвета и папки назначения.
- Копирование или перемещение файлов и папок, включая имена на русском языке.
- Переключение режима существующего портала через главное окно или контекстное меню.
- Обработка совпадений имён: переименование, пропуск, подтверждённая замена, отмена очереди.
- Фоновая передача, проверка копии SHA-256, анимация результата.
- Системный трей, сохранение расположения порталов, история последних 500 операций.

## Требования

Windows 10/11 x64. Для запуска готовой сборки Python не требуется. Для запуска исходников и сборки нужен Python 3.11+ и интернет при первой установке зависимостей. Проверенная среда: Windows 11 x64, Python 3.14.7, PySide6 6.10.2.

## Скачать готовую программу

Если к репозиторию приложен релиз, откройте **Releases**, скачайте архив `Portal-Windows-x64.zip` и распакуйте его целиком. Откройте папку `Portal` и запустите `Portal.exe`. Папка `_internal` должна оставаться рядом с EXE.

Если готового релиза нет, используйте запуск из исходников ниже.

## Запуск из исходников

1. Скачайте репозиторий через **Code → Download ZIP** и распакуйте архив.
2. Установите Python 3.11+ с [python.org](https://www.python.org/downloads/windows/), отметив **Add Python to PATH**.
3. Дважды нажмите `run.bat`. При первом запуске он создаст окружение `.venv` и установит зависимости.

Ручной запуск из PowerShell в папке проекта:

```powershell
python -m venv .venv
python -m pip --python .venv/Scripts/python.exe install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

## Сборка EXE

Дважды нажмите `build.bat`. Скрипт установит зависимости и PyInstaller, запустит тесты, соберёт приложение и проверит запуск EXE. Результат: `dist\updated\Portal\Portal.exe`. Для распространения упакуйте всю папку `Portal`, включая `_internal`.

Исходники, тесты и сценарии сборки хранятся в Git. Окружение Python и готовые сборки в Git не добавляются.

## Структура проекта

```text
main.py                     — запуск, иконка и системный трей
ui/main_window.py           — главное окно и история
ui/portal_window.py         — плавающий портал и drag-and-drop
ui/create_portal_dialog.py  — создание портала
core/file_transfer.py       — копирование, проверка и перемещение
core/portal_manager.py      — порталы и фоновые задачи
core/settings.py            — JSON-настройки
core/history.py             — журнал операций
tests/                      — автоматические проверки
Portal.spec                 — конфигурация PyInstaller
```

## Запуск

Откройте `dist\updated\Portal` и дважды нажмите `Portal.exe`. Сохраняйте всю папку вместе с `_internal`: один EXE отдельно работать не будет. Также можно дважды нажать `run.bat` в корне проекта. Перед запуском обновления завершите прежнюю версию через трей → «Выход». Порталы и история сохранятся.

Если сборки ещё нет: установите Python 3.11 или новее с python.org, отметив Add Python to PATH, и запустите `run.bat`. Первый запуск загрузит зависимости. Для повторной сборки используйте `build.bat`.

## Использование

1. Нажмите «Создать портал», укажите имя, существующую папку, цвет и режим. По умолчанию используется копирование.
2. Перемещайте портал по рабочему столу левой кнопкой мыши.
3. Перетащите файлы или папки из Проводника на портал. Дождитесь галочки. Во время передачи портал не принимает новые файлы; другие порталы доступны.
4. При совпадении имён выберите переименование, пропуск, замену с дополнительным подтверждением или отмену оставшейся очереди.
5. Правый щелчок по порталу открывает меню. Удаление портала не удаляет папку и её файлы.
6. Закрытие главного окна сворачивает приложение в трей. Значок может находиться под стрелкой скрытых значков возле часов. Выход — через меню трея. При активной передаче нужно дождаться завершения.

В настройках задаётся размер новых порталов. Режим существующего портала меняется кнопкой «Режим передачи» после выбора строки или через правый щелчок по порталу → «Режим передачи». Копирование оставляет источник, перемещение удаляет его после проверки копии. Смена монитора не меняет режим. Уже скопированные файлы автоматически не удаляются. Цвет выбирается при создании. История показывает последние 500 объектов, а не каждый вложенный файл папки. Полные пути и ошибки видны в подсказках ячеек.

## Сохранность данных

Копирование выполняется в отдельном потоке во временный каталог `.portal-transfer-*` внутри целевой папки. Содержимое проверяется SHA-256; итоговое имя появляется после проверки. Для перемещения сначала создаётся и проверяется полная копия, затем удаляется источник. Для папок нет слияния: подтверждённая замена заменяет папку целиком.

Если программа или компьютер аварийно выключились, в целевой папке может остаться `.portal-transfer-*`. `payload` — незавершённая или ещё не опубликованная копия; `previous` — прежний объект при замене. Не удаляйте такой каталог, пока не проверите источник, итоговый объект и резервную копию. Автоматическое восстановление и отмена перемещения не выполняются.

Не редактируйте исходники во время передачи. Проверки обнаруживают большинство изменений, но не обеспечивают блокировку файлов от других программ. При ошибке удаления исходной папки часть её файлов может уже быть удалена: полная проверенная копия остаётся в назначении. Источник не удаляется при ошибке копирования или проверки. Копирование больших файлов требует свободного места под полную копию; при замене старая версия также временно занимает место. Ошибки диска и прав отображаются в истории.

Ссылки, junction и специальные файлы отклоняются. Очень длинные пути зависят от настроек Windows, версии Python и файловой системы. Зашифрованные файлы, альтернативные потоки NTFS, ACL, заблокированные файлы и изменения файлов сторонними программами не имеют гарантий полного воспроизведения. Обычные файлы, подпапки и Unicode поддерживаются.

Настройки и история: `%LOCALAPPDATA%\Portal\settings.json` и `history.json`. История содержит полные локальные пути. Повреждённый JSON не перезаписывается молча: при запуске появится сообщение. Скопируйте файл в резервную копию и исправьте его или переименуйте для сброса. Второй экземпляр приложения блокируется. Порталы вне доступных экранов возвращаются на экран при запуске и отключении монитора.

## Проверка

В корне проекта выполните:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m compileall -q core ui main.py
```

Тесты создают только временные тестовые данные. Проверяются копирование, перемещение, папки, Unicode, все решения конфликтов, изменение источника, сбой записи, восстановление заменяемого файла, настройки, история и создание/удаление портала в Qt offscreen.

Ручная проверка Windows: создайте отдельные тестовые папки, перетащите один файл, несколько файлов и папку из Проводника; повторите с перемещением и одинаковыми именами. Проверьте все четыре решения конфликта, трей, перезапуск, перетаскивание самого портала и отключение второго монитора. Реальные пользовательские документы для проверки не нужны. Offscreen-тесты не заменяют проверку взаимодействия с Проводником и несколькими мониторами.
